# Database architecture

Recall uses PostgreSQL through SQLAlchemy's async engine and Alembic migrations.

## Core schema

- `users` owns all user-scoped records.
- `collections` belong to a user; deleting a collection returns its resources to the Inbox by setting `collection_id` to `NULL`.
- `tags` belong to a user. A unique expression index prevents two tags with the same case-insensitive name for one user.
- `resources` represent links, notes, and snippets. A database check constraint requires a URL for links and text content for notes and snippets.
- `resource_tags` records the resource–tag many-to-many relationship.
- `refresh_tokens` stores only SHA-256 hashes of refresh tokens, allowing server-side revocation and rotation.

All primary keys are UUIDs. User-owned records use foreign keys with explicit deletion behavior. Ownership matching between a resource and a tag or collection is additionally enforced by the authenticated service layer in later milestones.

## Migrations

Set `DATABASE_URL` to an async SQLAlchemy PostgreSQL URL, then run:

```bash
uv run alembic upgrade head
```

Create later revisions with:

```bash
uv run alembic revision --autogenerate -m "describe change"
```

Review every autogenerated revision before applying it. The current migration head is `20261102_0002`.
